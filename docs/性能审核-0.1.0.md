# 多终端性能审核（0.1.0）

审核日期：2026-10-23。基线：`30f913ac`。优化分支：`codex/terminal-performance`。

本轮覆盖 PTY／WebSocket 输出、xterm 调度和回放、快照持久化、React／Zustand 状态传播、daemon 临时历史、Agent／Hook 识别、侧栏轮询与隐藏窗口生命周期。结论来自源码调用链、自动化回归和局部基准；没有把这些结果当作真实桌面应用的 FPS、输入延迟或整体 CPU 降幅。

## 已修复的放大开销

| 问题与触发条件 | 根因 | 本轮处理 |
| --- | --- | --- |
| 多终端同时输出时互相等待 | 全局调度器每个动画帧只允许一个终端提交，分屏数量直接增加排队帧数 | `TerminalWriteScheduler` 每帧最多派发四个不同终端，4 ms 同步派发预算；保持可见／隐藏 3:1 公平轮转及每终端串行 |
| 最小化／托盘期间积压，返回后集中处理 | 输出完全依赖 rAF，WebView 暂停 rAF 时无法继续确认已接收输出 | 100 ms 计时器兜底，每轮一个批次；与 rAF 互相取消，空闲时无计时器。操作系统完全挂起进程时仍不能保证执行 |
| 每十秒出现与终端数相关的全局更新 | 每个脏终端保存快照都会替换 `sessions` 数组，唤醒所有订阅者 | 快照移入独立缓存，保存入队时合并为持久化对象；退出冻结、重挂、空画面和关闭清理共用同一数据来源 |
| 持续输出时全局订阅者反复计算 | `recordPtyOutputActivity` 每终端每秒更新共享 Zustand，实际只有 Hook 候选打分需要该时间 | 活动时间独立缓存，保留一秒节流和同步读取；Stop／失败及关闭时清理，乱序和子 Agent 事件不误清 |
| 输出积压越大，确认时越慢 | `TerminalProcessManager` 每确认一帧都对数组头 `splice`，排空呈二次复杂度 | 头游标推进、即时释放已确认内容、摊销压缩；保留顺序确认、去重和旧消费者隔离 |
| 后台长时间输出造成磁盘和会话锁竞争 | spool 超过 10 MiB 后，每移出一个 PTY 帧都重新读取和重写约 10 MiB | 保留原逻辑历史容量，维护帧索引与读取偏移，累计废弃约 10 MiB 再压缩；文件写成后才切换，失败保留重试状态 |
| 重连只需尾部数据，仍处理全部历史 | `oldest_sequence` 全量读盘，增量回放先全量复制／Base64 编码再过滤 | 最早序号查索引，按序号跳过旧磁盘内容，再读取所需帧；二进制传输直接复用原始字节 |
| 同一 checkpoint 重复等待产生轮询且掩盖失败 | 每个重复请求每 10 ms 检查 Map，主请求删除后无论成功失败都视为成功 | 共享原请求 Promise，成功、拒绝、超时、关闭和断连返回一致结果，无额外轮询 |

调度预算只约束同步派发和转换，不能约束 xterm 随后的异步解析总耗时；64 KiB 实时批次与最多四次派发限制解析工作量。回放帧保留原尺寸与边界，不强行拼接或裁剪。

spool 是 daemon 生命周期内的临时回放文件。正常单文件约不超过 20 MiB，压缩期间另写约 10 MiB；这是以有界临时空间换取更少磁盘重写。逻辑保留窗口仍为 10 MiB，不修改用户 CLI 历史，也不调整数据库迁移。

独立审核补齐两条失败路径：回放文件缺失或损坏时，在注册订阅及推进序号前拒绝附着，避免静默遗漏输出；压缩后旧文件暂时无法删除时保留其路径，在后续压缩、checkpoint 和关闭时重试清理。读写权限等持续异常期间不承诺上述正常文件空间上界。

## 后续审核的七项热点处理

以下是针对上一轮报告剩余热点的实现和边界；收益来自调用次数、扫描量及自动化行为验证，不代表已确定各项在用户实机负载中的占比。

| 热点 | 已实现处理 | 保留的语义与边界 |
| --- | --- | --- |
| Hook 每次全进程扫描 | 后台发现建立父子索引及 Agent 候选索引；macOS／Linux 的本地 Hook 定向读取当前终端子树和真实祖先链，Windows Hook 与常规后台发现通过 Job 列表和原生逐 PID 查询取得当前观察，不枚举全系统进程 | 每次重新读取启动时间和前台归属，不用 TTL 缓存充当身份凭据；首个 Hook、嵌套 Agent、独立 Agent 歧义及远端排除继续校验 |
| 每十秒全量序列化后裁剪 | 通过 xterm `serialize({ scrollback })` 直接生成约 2000 行尾部；首次脏保存、60 秒或累计提交 4 MiB 输出生成完整 checkpoint，阈值跨越后立即排任务 | 快照画面、网格、鼠标编码和 committed sequence 在同一冻结屏障内分片捕获；正常屏／备用屏、ANSI、光标、鼠标协议保持完整，退出强制捕获；序列化和上传失败保留重试 |
| TUI 提交与重绘重复扫描 | 使用公开 `onWriteParsed` 事件归一化，合并 Codex／Claude／输入提示识别；滚动与尺寸变化合并调度 | 同步归一化取消已排队扫描，自身 `refresh` 不再反向触发扫描；显示／主题变化仍处理，隐藏终端不扫描 |
| 跨会话统计刷新和无变化持久化 | 统计刷新序号按 session 隔离；身份比对后才更新元数据和入队保存，重复在途保存合并 | 观察时间保留在独立运行态缓存，旧 daemon 和乱序 Hook 不覆盖新身份；本地／WSL／SSH 动态绑定及持久化缺失自愈继续保留 |
| 隐藏窗口轮询及迟到结果 | 会话信息同时检查 document 和 Tauri 的可见／最小化状态；同作用域合并在途读取，生命周期失效后不更新当前面板 | 失焦但可见时继续更新；隐藏／托盘停止查询，恢复后主动刷新；Workspan、Worktree、SSH 上下文独立 |
| 每个组件各自查询 Git 分支 | 侧栏、状态栏、会话信息共用按规范化路径和环境索引的查询；共享 15 秒刷新，最多四个并发，值未变不通知 | Windows 路径去重，WSL 路径大小写和发行版语义保留，Worktree 分开，SSH 不调用本地 Git；取消订阅的排队项目不读取，实际隐藏时停止排队派发 |
| 二进制输出 Base64 往返 | daemon 内部实时输出、广播、缓存和回放使用 `Arc<[u8]>`；二进制 WebSocket 直接封装共享字节 | 仅旧 NDJSON／事件兼容边界编码 Base64；保持字段格式、队列容量计算、背压、附着屏障及输出顺序 |

后台无 Hook 发现仍保留每秒一次采样。macOS 使用 `proc_pidinfo`／`proc_pidpath`／`KERN_PROCARGS2` 和子进程接口，命令读取前后复核启动时间与父 PID；Linux 定向读取 `/proc`。Windows 正常 Hook 与后台采样直接查询 daemon Job PID 列表，再用 `OpenProcess`、`GetProcessTimes`、`QueryFullProcessImageNameW` 和动态解析的 `NtQueryInformationProcess` 读取相关进程。保留句柄至整批存活复核，祖先边使用完整 FILETIME，命令行返回缓冲区严格校验长度、对齐和指针边界；不读远程 PEB。Job 成员变化时最多额外重采一次，新出现的独立兄弟 Agent 仍进入歧义检查。命令不可读仅使其所属的未被已确认外层 Agent 覆盖的分支不确定；基础身份不可读时保守拒绝该次观察，不清空绑定。

只有 Job 不可用的异常路径保留后台每秒一次的全进程父子元数据扫描。Hook 自身不发起全扫描，释放 session／tracker 锁后，最多等待 1500 ms 取得请求到达后才开始的成功采样代次，再原生重读相关 PID；超时不修改已有身份。这不是 TTL 身份缓存，也不是所有环境下彻底取消全系统采样。线上的 `startedAt`／`runId` 仍沿用秒精度协议，原生祖先判断改用完整 FILETIME；本轮未改协议格式。

已有的隐藏 GPU 回收、内存／系统资源采样暂停、回答预览按可见性读取继续保留。不增加已移除的历史统计或供应商功能。

### 快照序列化局部测量

macOS arm64、Node v26.10.0，使用项目实际 xterm 与 serialize addon，120 列 × 32 行，ANSI 颜色和中文负载。预热后取五次中位数；可用 `node scripts/terminalSnapshotPerformance.mjs` 复测。

| 滚动历史 | 完整序列化 cell 访问 | 约 2000 行尾部 cell 访问 | 完整单次 | 尾部单次 |
| --- | --- | --- | --- | --- |
| 9000 行（含视口共 9032 行） | 1,110,903 | 245,967 | 56.111 ms | 9.923 ms |
| 50000 行（含视口共 50032 行） | 6,153,903 | 245,967 | 338.037 ms | 9.477 ms |

为了隔离序列化 CPU，以下对一个真实缓冲区重复读取 10／30／60 次，**不是同时挂载相应数量终端的桌面测试**；数字为该批读取的累计耗时：

| 滚动历史 | 10 次完整／尾部 | 30 次完整／尾部 | 60 次完整／尾部 |
| --- | --- | --- | --- |
| 9000 行 | 567.464／88.663 ms | 1725.397／269.333 ms | 3415.625／624.784 ms |
| 50000 行 | 3335.139／103.784 ms | 10077.640／282.707 ms | 20221.077／551.152 ms |

完整 checkpoint 加尾部捕获仍需读取全部必要 cell，未通过删减历史降低成本。本轮进一步把尾部和完整序列化改为可取消的分片状态机：每片 4 ms 预算、最多 32 个扫描／组装步骤，超宽行每 256 个 cell 也可让出；先按 32 KiB 平坦化字符串，再做最终拼接，避免把长任务移到末尾。使用真实任务队列，不依赖 rAF，隐藏窗口也可推进；保留固定上游 xterm 版本和 MIT 归属，升级依赖时由字节等价测试校验。

捕获前冻结当前终端的新 write、resize、reset、clear、scrollback 设置和 TUI cell 修改；旧 parser 队列、回放提交微任务完成后，再读取画面、尺寸、序号和鼠标编码。排队的输出不提前 ACK，resize 不同步冲刷下一段待解析回放；窗口 reflow 的 viewport marker 也在实际 resize 时计算。reset 到达与实际提交分别管理，等待 reset 完成时不持有冻结屏障；跨 stream generation 的捕获重试，重连发送前与本地持久化前复核代次。取消、错误、卸载均释放或销毁队列，其他终端继续运行。

同一环境新测量（五次中位数，`node --expose-gc scripts/cooperativeTerminalSerializerPerformance.mjs`）：

| 缓冲区行数 | 原始同步完整捕获 | 分片最大连续处理时间 | 默认调度完整耗时 |
| --- | --- | --- | --- |
| 9,032 | 63.967 ms | 1.890 ms | 79.756 ms |
| 50,032 | 344.723 ms | 1.707 ms | 422.363 ms |

50,032 行五次中最慢单片为 1.813 ms，最终拼接中位数 1.707 ms；1 ms 计时器在默认完整扫描期间得到约 112 次调度，最大间隔中位数 8.642 ms。时间预算不是硬实时上限，GC、设备和负载均会影响结果。这些是 Node 中真实 xterm 的序列化／任务让出实验，不是 WebView FPS 或键入延迟测量。

代价是当前终端的解析／ACK 在完整捕获期间暂停，上述大缓冲区约 0.42 秒；输入与其他终端可继续调度，原有背压限制积压。正常定时和退出 checkpoint 使用分片路径。React 卸载无法异步等待，优先 `finishSync()` 续完已有完整扫描，未在扫描时仍保留同步全量快照兜底；这一低频卸载开销尚未消除。

4 MiB 阈值基于已提交输出，正常连接下早于 daemon 2 MiB 内存环加 10 MiB spool 窗口耗尽，并保留原背压。操作系统完全挂起、严重调度延迟或长期存储／传输失败时仍受原有有限回放窗口约束，不能承诺任意长断连后的全量历史。
